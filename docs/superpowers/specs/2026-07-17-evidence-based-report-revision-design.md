# Dobot Magician 证据型完整修订设计

## 1. 目标

在保留原有学院 Word 模板、封面、考核表、页眉页脚和章节层级的前提下，对《基于 GMM-GMR 运动基元的 Dobot Magician 夹爪码垛轨迹学习仿真研究》进行一次证据型完整修订。修订不仅补充图片，还要同步当前代码、配置、模型结果和复现手册，解决旧报告中数据过时、图文脱节以及只有轨迹曲线而缺少系统与仿真证据的问题。

最终报告必须准确描述为“基于 CoppeliaSim 简化夹爪场景的单点码垛轨迹学习仿真”。报告不得暗示已经实现真实 Dobot Magician、完整机械臂运动学、物理抓取、碰撞检测或避障。

## 2. 事实来源与使用边界

修订只使用下列可追溯来源：

1. 当前仓库中的源码、配置、测试、合成示教 CSV、模型文件、指标表和正式场景文件。
2. 用户从当前模型回放视频中截取并确认的真实视频帧，以及当前场景的只读截图和对象读取结果。
3. 用户提供的原论文 PDF 和答辩 PPTX，用于建立“论文方法与当前简化复现”的对照关系。
4. 原始正式报告 `reports/基于GMM-GMR运动基元的Dobot Magician夹爪码垛轨迹学习仿真研究.docx`。

下列内容不得作为报告证据：

- 已被用户判定为假的补充图片版及其生成图。
- 根目录中的 `.codex_tmp_source*` 豆包临时文件。
- 没有对应源码、配置、运行结果或明确文献出处的生成式示意图。
- 2026-07-06 的旧回放视频，除非明确标注为历史基线。正式修订中的回放过程图使用用户确认的当前模型视频帧。

## 3. 当前报告必须同步的内容

### 3.1 指标与结论

以 `models/algorithm_metrics.csv` 和 `models/algorithm_metrics.md` 为唯一当前指标来源：

| 算法 | Pearson Mean | RMSE Mean |
| --- | ---: | ---: |
| GMM+GMR+DMP | 0.9871 | 0.0187 |
| Inc-GMM+GMR+DMP | 0.9927 | 0.0123 |
| GMM+GMR+Segmented DMP | 0.9934 | 0.0139 |
| BGMM+GMR+ProMP | 0.9867 | 0.0205 |

讨论必须改为：分段 DMP 的 Pearson 均值最高，Inc-GMM+DMP 的 RMSE 均值最低。不能继续写“分段 DMP 两项指标均最好”或“BGMM 综合表现仅次于分段 DMP”。同时说明这只是同一组合成数据上的轨迹重构指标，不代表任务成功率、避障能力或实机性能。

### 3.2 参数

第 4.1 节按算法分别列出当前配置，至少包括：

- GMM+GMR+DMP：8 个 GMM 分量，15 个 DMP 基函数。
- Inc-GMM+GMR+DMP：增量阈值 `inc_lam=0.25`，50 个 DMP 基函数。
- GMM+GMR+Segmented DMP：8 个 GMM 分量，4 个近等长片段，每段 35 个 DMP 基函数。
- BGMM+GMR+ProMP：8 个候选 BGMM 分量，25 个高斯基函数，基函数宽度 0.08。

报告需明确当前分段实现使用 `numpy.array_split` 将 150 点 GMR 参考轨迹分为 4 个近等长片段，实际长度为 38、38、37、37 点，并非论文中基于碰撞、RRT 路径或任务事件确定分段点的完整方法。

### 3.3 当前结果图

图 4-1 至图 4-5 全部以 `models/` 当前输出重新同步，避免一部分图来自旧基线、一部分图来自当前基线。图注和正文分析必须与新指标一致。

### 3.4 复现命令

报告和接手手册记录当前 8 条合成轨迹的精确基线命令：

```powershell
python -m dobot_bgmm_promp.scripts.generate_palletizing_demos `
  --output-dir <空目录> `
  --n-per-pose 8 `
  --seed 42
```

必须注明生成器会追加编号，因此基线复现应使用空目录，不能反复写入已有数据目录。

## 8. 验证与质量标准

### 8.1 代码和数据验证

- 原算法基线使用 `python -m pytest tests/test_bgmm_promp.py -q -p no:cacheprovider`，输出 `5 passed`。新增证据图与报告 QA 测试后，全套 `python -m pytest -q -p no:cacheprovider` 也必须全部通过，并在验收记录中写明本轮实际用例数，不能继续把全套测试总数写死为 5。
- 从 `models/algorithm_metrics.csv` 自动核对 Word 和 Markdown 中的指标值。
- 核对 Word 嵌入的五张结果图与当前 `models/` 文件哈希或像素内容一致。
- 用户提供的回放截图记录视频对应的模型和录制日期；只有视频本身或运行记录能够证明时，才记录配置、时间或关键帧索引。

### 8.2 DOCX 结构验证

- 在工作副本中编辑，原始 DOCX 在视觉 QA 完成前不覆盖。
- DOCX 包可正常解包、重新打包和打开，不出现修复提示。
- 封面、考核表、目录域、页眉页脚、节设置和已有样式保持不变。
- 新图片有唯一关系 ID、正确媒体类型和合理尺寸。

### 8.3 逐页视觉验证

- 将最终工作副本转换为 PDF，并把全部页面渲染为 PNG。
- 检查每页的图片清晰度、中文字体、图注、分页、表格、目录、页眉页脚和页码。
- 不允许图片裁切、文本重叠、空白页、孤立标题、图注跨页或低清晰度截图。
- 只有全部页面通过检查后，才生成最终交付 DOCX；原始报告保留为基线或由用户明确决定是否替换。

## 9. 非目标

本次修订不实现 RRT、障碍物检测、碰撞规划、完整 Dobot 模型、IK、真实接触抓取或实机控制。这些属于后续研发项目，不能为了让报告看起来接近论文而加入没有代码和实验支持的结果。

本次也不把已有曲线简单换成柱状图来应付“图片更多”的要求。核心增量必须是真实系统结构、实际仿真环境和回放过程证据。
